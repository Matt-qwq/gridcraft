**Stage: alpha** · large-workbook beta gate met · next: beta, ~24 points of "ready for real work" and ~71–127 h away

is the native format), fully scriptable by agents (MCP, control channel, CLI), and on the web.

Each tier is a subset of the one above, so its hours are too. Calibrated as in [Effort and
calibration](docs/target-app-parity.md#effort-and-calibration) (~6–10 h per readiness point for the remaining, verification-heavy
work; single features measured from PRs #66, #100, #101). Parallelism: the full and mainstream
work splits ~65–70% across 4–6 agents by area; the essentials work is mostly small fixes plus one
long `.xls` track, so about half parallelizes (≈30–50 wall-clock hours with three agents).

Why alpha: all six core workflows in the [alpha gate](docs/roadmap.md#alpha-gate) pass end to end
on macOS with save and reopen, and the large-workbook beta gate is now met: 100M cells open with
16.7 MiB live / 183 MiB peak, independent formulas recalculate on the machine's threads (100k edit
20–25 ms), row and column structural edits are maps rather than cell moves, and whole-sheet data
commands are bounded. The remaining beta work is evidence and fidelity: nobody has yet confirmed
that **Excel** opens our output without a repair prompt across a real corpus (#1) — Excel itself is
not licensed on the dev machine, so a foreign reader (openpyxl) and a foreign application (WPS) stand
in for it ([oracle.md](docs/oracle.md)) and one Excel run stays the owner's — there is no
`.xls` or password support (#7), Arabic/Devanagari/Thai text is not shaped and non-Latin PDF is
weak (#5), charts lose options (#4), PivotTables lack slicers (#8), keyboard key tips remain (#9),
and the stability soak is not final (#10). Beta needs those closed (see
[beta gates](docs/roadmap.md#beta-gates)).

The 2026-10-07 numbers (catalog 89%, "feature depth ~65%", "~215 h to full parity") were
re-measured. Catalog and function counts held or rose; the depth and hours moved because of new
evidence: 82 issues filed by users and contributors in the repo's first five days, and scope the
old estimate left out (localization, legacy `.xls`, Power Query and the data model,
collaboration, mobile, AI).

## Progress log

| Date | What landed |
|---|---|
| 2026-11-02 | **High contrast, and the sheet is walkable by a screen reader.** View ▸ Show ▸ **High Contrast** (`view.highContrast`, keytip WVI — Excel takes this from the OS, GridCraft makes it a preference kept in `ui.json`) repaints the chrome black, white and yellow: white text and yellow separators on a black window, ribbon, tab bar and status bar, a yellow selection border and header highlight, cyan accents, and the sheet keeping its own white page and black text as Excel's high-contrast themes do; egui's own widgets (menus, dialogs, tooltips) are darkened with it so their text stays readable. Earlier the same day the **visible cells became an AccessKit grid** for screen readers: one `GridCell` per visible cell (value, address and formula, row/column index, the active cell selected and named as the grid's active descendant), `ColumnHeader`/`RowHeader` nodes for the visible headers, frozen panes included, rebuilt only while a reader is attached and capped at 2,000 cells |
| 2026-11-02 | **A screen reader can walk a sheet.** The grid is painted as one surface, so AccessKit used to see a single node; now, **while a reader is attached**, the visible cells become an AccessKit grid: one `GridCell` per cell with its displayed value, its address and formula in the description, its row and column index, the active cell marked selected and named as the grid's **active descendant** (so a reader announces the cell as the container's active item), and the grid labelled with the sheet, the active cell and the selection count. Frozen rows and columns are included and the tree follows scrolling; with no reader attached nothing is built beyond a probe (one branch a frame), and the walk is capped at 2,000 cells so a large window costs bounded work — a reader scrolls for the rest as a sighted user does. The header row and column are `ColumnHeader`/`RowHeader` nodes (letters, numbers, indexes) and the grid node carries its own bounds. The cells are hover-only nodes, so clicks, drags, the fill handle and the scroll wheel keep going to the grid's own pointer handling, which the pointer tests re-check |
| 2026-11-02 | **Charts, pictures and shapes can be described, and the check goes to what it finds.** Alternative text is modelled for charts (`Chart::alt`) and shapes (`Shape::alt`) as pictures already were, written as `xdr:cNvPr/@descr` on every drawing frame the writer makes (a chart, a kept chart, a shape and a picture; escaped, so a quote or an angle bracket in a description cannot break the part) and read back, with `object.setAltText` to set or clear it. **Review ▸ Check Accessibility** now reports charts, pictures, shapes with no text of their own and pictures in cells without alt text, tables without a header row, merged cells and sheets still on their default name, each with its sheet and object or range; its dialog lists them, **goes to** each one (selecting the object or the range) and takes alt text inline, so a screen reader's description is set from where the problem is seen. The accessible tree for the grid itself (cells, headers, the selection) is still to come |
| 2026-11-02 | **A PivotTable filter knows which area it belongs to.** A field can sit in the Filters area *and* on an axis at once (a file says so with a `pageFields` entry), but a filter carried no area, so both the writer and the refresh guessed it from whether the field was in Rows/Columns — a page filter on an axis field collapsed into hidden items and lost its row above the table. `PivotFilter` now records its area (`Auto` for documents written before it existed, `Page` for the Filters area, `Axis` for hidden items), the reader sets it (`pageFields` vs `item/@h`), the writer and the refresh honour it, and moving a filtered field onto an axis turns a page filter into an axis filter (a field is in one area at a time). xlsx test: `pageFields` survives for an axis field and is not written for an axis filter; engine test: the report-filter row is drawn only for the page area |
| 2026-11-02 | **A data label carries its own font, and gate #4 closes.** A label's size, weight and colour are modelled at three levels — the chart's (`c:dLbls/c:txPr`), a series' and a point's (`c:dLbl/c:txPr`) — read from `a:defRPr` (`sz` in hundredths of a point, `b`, the `solidFill`), written back, patched in place, and drawn: the levels combine **field by field**, so a point that sets only a colour keeps its series' size and the chart's weight, and the renderer draws the size, colour and weight it ends up with (a hostile size is clamped to a drawable one). `chart.setDataLabels {fontSize, bold, color}` sets it at any level and the Format pane's Data Labels and Data Point sections carry a size field, a weight box and a colour menu; a chartex chart's label font is refused with the reason rather than stored and dropped. With the per-point marker size, click-to-select and the pane's custom error bars landed the same day, the chart gate is met — what is left (chartex granularity, a pane per shape/picture) is outside it |
| 2026-11-02 | **A chart element is selected by clicking it.** The renderer used to return only primitives, so the Format pane's dropdown was the only way to pick an axis or series; it now returns the primitives **and the boxes a click can land on** (`gridcraft_chart::draw` → `Drawing { prims, hits }`, `hit_at` taking the topmost region), which means the hit test is the drawing's own geometry and cannot drift from what is on screen. A bar, an area band, a bubble or marker, a line's data point, a pie/doughnut/sunburst slice (an exact wedge region, not its bounding box), a legend entry and an axis' label band each name their series and, where one point was hit, that point; regions are capped at 4,096 per drawing so a chart with more points than that is edited through the dropdown only. The first click on an unselected chart selects the chart and resets the pane to the chart area (Excel's two-step gesture), the next click picks the element under the pointer, a click on the frame's padding goes back to the chart area, and the Data Point section follows the clicked point. Four chart tests pin a click on every bar region, the axes, each slice's bisector and hostile coordinates; two UI tests drive real pointer input and check the pane's selection and point number |
| 2026-11-02 | **A chart point carries its own marker size, and a custom error bar its references.** `PointFormat::marker_size` (2–72 points) is read from `c:dPt/c:marker/c:size/@val`, written, patched, drawn at that radius (`size × 0.7` px, 5 pt where a point sets only a colour) and settable from `chart.formatPoint {markerSize}` and the Format pane's Data Point section; a point that sets only a size writes its own marker element (with the default 5 pt written where only the colour is set), even on a series whose marker is switched off. The command refuses a size outside 2–72 and a series whose points do not draw markers, instead of storing an option nothing shows. The **Error Bars** section's Custom kind now edits the plus and minus referenced ranges through `chart.setErrorBars`, so a custom error bar no longer needs a command line to change. Engine test drives formatPoint through save/reopen and the xlsx and chart round-trip tests pin the attribute and the radius; a pane test types the size field |
| 2026-11-02 | **A series moves to the secondary axis.** `chart.setSeriesAxis {series, secondary?, type?, subtype?}` is the model side of Change Chart Type → Secondary Axis: it moves one series onto the right-hand value axis, optionally changes that series' kind, and turns the chart into a combo; the Format pane's Series Options carries the checkbox. Reading a combo chart back had returned its series in the writer's group order (primary bars, primary lines, secondary), so a series index from before a save pointed at another series after reopen — the reader now sorts by `c:order`/`c:idx`, and a secondary line group keeps its markers when written. Engine test drives the command through move, axis bounds on `y2`, save/reopen and back; an xlsx regression reads an out-of-order-group file; a pane test clicks the checkbox |
| 2026-11-02 | **A timeline's range is edited on the sheet.** The track is drawn as the field's own date axis and the selected range as a band with its own handles: dragging an end resizes the range, dragging the band slides it without changing its length, both snap to whole days, stay inside the axis and never cross. Each drag runs `slicer.setRange` and coalesces into **one undo step** (Esc restores the range), and the field's bounds — a scan of the report's source — are computed once per document revision and cached in the grid, so a drag does not rescan the source every frame. The engine exposes `cmd::slicer::timeline_axis`; five pure mapping unit tests and four harness tests drive real pointer input over a selected band, release/undo and a timeline whose report is gone |
| 2026-10-30 | **A slicer follows the names it binds to.** A table slicer stored the table's name and the column's header at insertion, so renaming either left the widget pointing at something that no longer existed: `table.rename` left the tiles empty and the filter unapplied, and a header-cell edit left `Slicer.column` on the old name. Both now follow the rename in the same undo step — the header path through `sync_headers`, so a structural edit that rewrites headers carries the widget with it — and a caption that still shows the old name follows while a custom caption stays. `insert.slicer` also applies the documented `caption` param now (it was dropped). And a filter changed from the **report** — `pivot.filter`, or any update that rewrites the pivot's filters — mirrors onto a slicer connected to the field when every connected report agrees and every label names a tile; a grouped date or number-format label has no tile, so the widget keeps its state rather than showing a selection the model does not hold. Three engine regressions, the tile/undo one first red |
| 2026-10-30 | **A whole-column fill wrote two million cells where the sheet had 84.** The narrowing that makes a whole-row/whole-column fill cover only the lines it fills was resolved against the sheet's **used-range bounding box**, so a single stray cell far down the sheet made a `Ctrl+D` on two whole columns write 1,048,576 rows — and the soak then spent 415 s per seed on a 2–6M-cell workbook while every per-step invariant ran over millions of cells. The fill now narrows to the content **in its own lines** (spilled arrays included): that step went from 2,097,102 cells and 830 ms to 50 cells and under a millisecond, and the seed from **415 s to 5 s**. Stated behaviour change: on a whole-line target whose own lines end above the sheet's used-range bottom, the fill stops at the lines' content — whole-sheet selections, explicit ranges and the ordinary case are unchanged. `pasteSpecial` also looked each moved cell up by scanning a list (quadratic): 25/90/332/1,322 ms at 10k/20k/40k/80k rows became 10/20/67/97 ms. Three time tests with 10× budgets pin both, and the measurement also settled that the reported "freeze in `deleteColumns`" is not one — that command costs 40 ms there |
| 2026-10-30 | **A chart keeps its own look.** A chart's `styleN.xml`/`colorsN.xml` are read from its relationships and written back **byte-identically** — for chartex *and* for classic charts, the latter now kept at all when their only relationships are style/colour parts, which real Excel files usually have. They survive a field patch (a title edit rewrites only the title element, as before) and are dropped only when the part must be regenerated — a kind, series-set or reference change — with the default written in their place and the rule stated in `chart-parity.md`. A style part that is not UTF-8, is over 4 MiB or is not XML degrades to the default with a warning rather than being rewritten lossily. **And one claim retired instead of faked:** a per-point label prefix/suffix does not exist in either schema — `c:dLbl` carries `tx` (a cell reference or rich text, which replaces the composed label) and chartex's `cx:dataLabel` has no text element at all, so the work item is gone from the checklist with the reason recorded (#4) |
| 2026-10-30 | **Table column names have one rule, applied in memory.** A table over blank cells is named `Column1..N`; resizing it one column to the right dropped the old first column and added a blank one, and the blank third header got the position-derived `Column3` that the shifted second column already had — a **duplicate** the model kept. `sync_headers`, the reconciler, only looked at cells that changed and deduped through a `name → column` map, which cannot represent two columns sharing a name, so both halves of the duplicate matched their own column and were skipped. The writer then did exactly what it documents for a malformed model: unique names, the later one renamed — `Column3` → `Column32`, written into the header cell. That rename at the file boundary, by a rule nothing in memory had applied, is the corruption: no undo can reach it. Now one function (`header_names`) owns the rule — blank header takes the first free `ColumnN` at or after its position, a repeat takes the first free `{name}{k}` from 2 on the later column, both searches bounded — and `sync_headers` reconciles the **whole** header row after a structural edit, so the model, the cells and the file cannot disagree. Five regressions, all red without the fix |
| 2026-10-30 | **An array that reads its own spill is circular — a fixed point the pass could not reach.** `G25 =UNIQUE(D15:G20)` spills into `J25`, and `F20` sits *inside* `UNIQUE`'s source range and reads `J25` from that spill: a circular reference whose area is only known once the array is computed, so the static dependency graph cannot name it. The pass then oscillated (array spills → `J25` filled → `F20` changes the source row → the array needs two rows → blocked → `J25` empty → …) and stopped after the eight-round cap on whichever side it started from, so **both** answers were wrong — `"-"` is not a fixed point either while the array spills.
