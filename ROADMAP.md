# GridCraft roadmap

**Stage: alpha** · large-workbook beta gate met · next: beta, ~25 points of "ready for real work" and ~94–162 h away

> **Last reviewed:** 2026-10-30 · **Last updated:** 2026-10-30 · **Change:** minor (PivotTable slicers and timelines modelled and command-driven, a selection filters the pivot; chart edits patch the kept part, unmodelled kinds kept whole, secondary axis; gates #6 and #7 hardened, #4 2–6 h and #8 14–22 h; beta ~94–162 h) · **Target:** Microsoft Excel (Microsoft 365)

GridCraft aims at full Microsoft Excel parity, and at being better in places: faster, open (XLSX
is the native format), fully scriptable by agents (MCP, control channel, CLI), and on the web.
This page is the summary. The detail is in:

Each tier is a subset of the one above, so its hours are too. Calibrated as in [Effort and
calibration](docs/target-app-parity.md#effort-and-calibration) (~6–10 h per readiness point for the remaining, verification-heavy
work; single features measured from PRs #66, #100, #101). Parallelism: the full and mainstream
work splits ~65–70% across 4–6 agents by area; the essentials work is mostly small fixes plus one
long `.xls` track, so about half parallelizes (≈30–50 wall-clock hours with three agents).

Why alpha: all six core workflows in the [alpha gate](docs/roadmap.md#alpha-gate) pass end to end
on macOS with save and reopen, and the large-workbook beta gate is now met: 100M cells open with
16.7 MiB live / 183 MiB peak, independent formulas recalculate on the machine's threads (100k edit
20–25 ms), row and column structural edits are maps rather than cell moves, and whole-sheet data
commands are bounded. The remaining beta work is evidence and fidelity: nobody has yet confirmed
that Excel opens our output without a repair prompt across a real corpus (#1/#3), there is no
`.xls` or password support (#7), Arabic/Devanagari/Thai text is not shaped and non-Latin PDF is
weak (#5), charts lose options (#4), PivotTables lack slicers (#8), keyboard key tips remain (#9),
and the stability soak is not final (#10). Beta needs those closed (see
[beta gates](docs/roadmap.md#beta-gates)).

The 2026-10-07 numbers (catalog 89%, "feature depth ~65%", "~215 h to full parity") were
re-measured. Catalog and function counts held or rose; the depth and hours moved because of new
evidence: 82 issues filed by users and contributors in the repo's first five days, and scope the
old estimate left out (localization, legacy `.xls`, Power Query and the data model,
collaboration, mobile, AI).

## Progress log

| Date | What landed |
|---|---|
| 2026-10-30 | **Encryption is verifiable now.** Keys and salts come from the operating system's CSPRNG instead of stretched SipHash seeds, the Agile `dataIntegrity` HMAC is **verified on read** after the password check (both fields decrypted with the package key under their own block keys' IVs, constant-time compare, segments must cover the stated size), and `Corrupted` is a distinct failure so a damaged file stops reading as a wrong password. The web build **refuses** a password-protected save with a normal command error rather than writing predictable salts. Two defects fell out of building an independent oracle (a dev-only CFB reader, plus a from-the-spec Python run): the landed writer had encrypted the two integrity fields with a password-derived key and one shared block key, which [MS-OFFCRYPTO] does not allow — Excel would have rejected our files — and the mini FAT's last sector was zero-padded, where a zero entry names mini sector 0 (#7) |

| 2026-10-30 | **The formula engine now has an oracle.** 595 documented examples over **275 functions**, evaluated through the real calc path (`gridcraft_calc::evaluate`) with fixtures, plus dedicated tests for real spills, `#SPILL!` unblocking, the 1904 date system, 3-D references and qualified names: lookup and array lifting, financial, date/time (including the 1900 leap bug), text, statistical, math, engineering, info and database functions, with the expected value taken from Microsoft's published example and cited per row. It is labelled for what it is — **documentation-derived, not Excel-computed**. It found no disagreement in the implementation; every mismatch was a transcription error on the way in, which the documented rule resolved (VLOOKUP's approximate ladder, LOOKUP above the largest key, DOLLAR's accounting parentheses, DDB with a low factor, DATEDIF's 730 days, DAYS360, WORKDAY over three holidays, SUMIF's omitted sum range). 95 calc tests (#6) |
| 2026-10-30 | **Charts got their UI.** The Format pane drives the four chart commands for the chart area, either axis and each series — Format Axis with per-field **Auto**, Format Data Labels, Error Bars, Format Data Point — and an option a chart kind cannot store is not offered, with the reason shown in the section instead of a dead control (a pie's axes, a chartex part, bounds on a label axis, a marker on a column point). Objects **resize from all eight handles** now (charts, pictures, shapes, slicers; before, only the bottom-right corner resized and grabbing any other handle moved the object): one `object.move` per frame carries the anchor and the extent, so a left/top edge drag moves both; Shift keeps the aspect ratio, 20 pt minimum, Esc cancels without leaving an undo entry, a whole drag is one undo step, arrow keys nudge 10 pt (1 pt with Ctrl, one step per press), and the size survives save → reopen. ui-egui 979 tests (#4) |
| 2026-10-30 | **Slicers and timelines are real objects, not kept blobs.** A slicer's cache field, the PivotTables it filters, its item values with the selected tiles, name, caption, style, column count, timeline unit and anchor are read into the model and written back **once from the model**, so `insert.slicer` (pivot or table), `insert.timeline`, `slicer.setSelection`, `slicer.setStyle`, `slicer.move` and `slicer.delete` all drive it — and a selection **really filters**: it writes the field's `PivotFilter` on every PivotTable in the cache list and runs the pivot's own refresh path inside one undo step, and the filter survives save → reopen. Content we cannot model (an OLAP cache, item properties, an unknown attribute or relationship, a timeline's date range) stays byte-identical on the pass-through path, all-or-nothing per kind so a partly understood cache never gets half-rewritten. Catalog 280/295. Two honest gaps: the slicer's placement shape is not written (Excel lists it without placing it) and the widgets are not drawn in the UI yet; a filter on a field outside Rows/Columns shows as an extra page-filter row because `PivotFilter` cannot mark itself as slicer-only (#8) |
| 2026-10-30 | Chart edits now **patch the part they came from** instead of rewriting it: changing one option rewrites only that element and leaves every other byte alone (the test deletes the patched element and compares the rest to the original), so unmodelled content that used to die on the first edit survives — manual plot-area and label layout, label callouts and leader lines, `dTable`, `serLines`, `overlap`, date-axis units, minor units and gridlines with their formatting, axis `spPr`/`txPr`, legend entry and title-run formatting, series `extLst`, `printSettings`. Turning labels off keeps the `dLbls` element with Excel's `delete` flag, so its callouts stay. Charts of kinds we do not model (3-D bar/line/area/pie, surface, pie of pie, bar of pie, Pareto, filled map) are no longer dropped or flattened to 2-D: the chart part and its drawing frame are kept byte-identically with a note that they are kept but not drawn. The **secondary axis** is modelled, written, patched, drawn (right-hand tick labels and display-unit name) and addressable with `chart.setAxis axis: "y2"`; category-axis bounds now crop the drawn window. Still lost: chartex options on modelled chartex kinds, per-point label text and position, per-point marker size. xlsx 306, chart 52, engine chart 20 (#4) |
| 2026-10-29 | Password-protected workbooks can be **saved**: `file.save`/`saveAs`/`saveBytes` write Agile encryption (AES-256-CBC, SHA-512, spin count 100,000, random salts, HMAC-SHA512 integrity, version-3 compound file), and a document opened with a password re-encrypts with it on a plain save — the silent removal of a file's protection is fixed. An empty password removes protection; a password on a format that cannot carry one is **refused, never dropped**. `.xls` gained a real style table (`FONT`/`FORMAT`/`PALETTE`/`XF`/`STYLE` → family, size, bold/italic/strike/underline, palette colour, number format, fill, four borders, alignment, protection, named styles) with cells picking up their XF, and `NOTE`/`TXO` comments with author and text; the record layouts were calibrated against an independent BSD-licensed BIFF8 reader over 70 Excel-authored files (metadata only, nothing copied in). Standard/RC4 encryption, `.xls` DV and conditional formats, BIFF5, hyperlinks and freeze panes remain (#7) |
